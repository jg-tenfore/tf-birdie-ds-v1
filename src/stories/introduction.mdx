## What this is

This Storybook is a **specification, not a shipping app**. Birdie POS will be built in
Expo/React Native; this library exists so that the layout, spacing, type scale, color, and
interaction rules are settled, visible, and testable _before_ they are translated to native.

Material UI is used as the vehicle because it implements Material Design — the same design
language Android tablets already speak — so patterns proven here carry over to the device
with their semantics intact.

## The constraint that shapes everything

**The counter terminal is a landscape tablet, and it is not responsive.** The reference device is a
10" Android tablet at **1280×800**, operated standing, by finger, at roughly arm's length. No
portrait layout, no breakpoint, no collapse to a hamburger.

**The handheld is a second surface, not a breakpoint.** `Mobile Screens` documents the same app at
**402×797**, and it is a genuine re-layout rather than the tablet reflowed: a 390px order panel
beside a content pane has no responsive path to a bottom-nav phone. The two are built and read side
by side, folder for folder.

Three consequences run through the whole system:

| Constraint               | Rule                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Fingers, not cursors** | Nothing tappable is under **48dp**. Primary actions are 56dp, tender keys 64dp, irreversible actions 80dp. Hover is never load-bearing.          |
| **Wide, not tall**       | 800px of height is the scarce resource. Chrome is capped at 136px total; content panels scroll internally, the page never does.                  |
| **Glanceable**           | Body text starts at **16px**, buttons are sentence case, and the brand green is reserved for _the_ action — so the eye finds it without reading. |

## How it's built

- **React 19** + **TypeScript**, files in kebab-case
- **Material UI v9** with the **Emotion** style engine and CSS theme variables (`--mui-*`)
- **Storybook 10** (`@storybook/react-vite`) for documentation and visual review
- Theme in `src/theme/` — [`tokens.ts`](?path=/docs/foundations-colors--docs) holds the raw values,
  `birdie-theme.ts` encodes the tablet rules as MUI component defaults

### Why the theme matters more than the components

The component overrides in `birdie-theme.ts` are the real deliverable. A plain `<Button>` is
56dp tall here, a plain `<IconButton>` is 48dp, a plain `<TextField>` is 56dp — because a
screen assembled from stock MUI components should be tablet-correct **without anyone
remembering the rules**. When these get ported to Expo, port the theme first.
